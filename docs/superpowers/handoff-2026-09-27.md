## Item 3: Harden the card layout (do first)
- **Problem:** in WebKit, inline `code` that wraps at the end of a line leaves its padding out of the line width, so it can overflow sideways. CI's Linux WebKit uses wider fallback fonts (about Verdana plus a Courier-width mono, Liberation Mono) than iOS.
- **Fix:** in the `code` style (src/ui/tokens.css), change `box-decoration-break: clone` (and the `-webkit-` prefix) to `slice`.
- **Headroom:** `c-claude-md` has 0px slack under a Courier-width code font. Give it headroom by tightening its wording only: no new facts, re-check against its source.
- **Local check:** force Verdana plus Courier New on the card to reproduce CI. The e2e card-fit tests (e2e/, WebKit iphone project) already cover all 155 cards in both directions.

## Item 4: Pin the CI runner
- `.github/workflows/deploy.yml` uses `runs-on: ubuntu-latest` in both jobs. GitHub moves `ubuntu-latest` to Ubuntu 26 on 2026-10-19, which could change fonts and break the card-fit check. Pin both jobs to `ubuntu-24.04`.

## Item 5: Error-handling pass
These writes are fire-and-forget, so a failure is silently lost:
- `void recordAnswer(...)` in src/features/practice/QuestionRunner.tsx
- `void toggleFlag(...)` in src/features/shared/FlagButton.tsx
- `void saveMockSession(...)` / `void submit()` in src/features/mock/MockExamPage.tsx. `submitting.current` stays true if `submitMock` rejects, so the user can never retry.
- `void markLessonDone(...)` in src/features/learn/LessonCheckPage.tsx
- `void navigator.storage?.persist?.()` in src/main.tsx
- `registration.update()` in src/pwa/UpdateBanner.tsx (no `.catch`; it logs an unhandled rejection every hour while offline)

Suggested design: a small app-level toast ("Couldn't save your progress, try again"), wired through ProgressProvider or a tiny notifier context, plus `.catch` on the background calls. Reset `submitting` on failure. Add tests for each path.

## Item 6: Stricter backup import and a consistent export
- src/storage/backup.ts `parseBackup` validates shallowly. Add checks for:
  - attempt `mode`
  - mock-session fields (`startedAt`, `durationMs`, `answers`, `flagged`, `currentIndex`)
  - FSRS numeric fields
  - invalid dates (reject `Invalid Date`)
- src/storage/db.ts:
  - `exportAll` should read every store in one read-only transaction (kv keys and values could otherwise misalign).
  - `addAttempts` and `replaceAll` call `Promise.all` before awaiting `tx.done`, which can leave an unhandled rejection. Include `tx.done` in the `Promise.all`, the way `putCardStates` does.
- Add tests: a damaged file (correct header, bad data) is rejected, a wrong-version file is rejected, and `putFlag` round-trips.
