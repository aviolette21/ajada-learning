Model Selection & Optimisation
Your app sends the same 20k-token system prompt on every request. What cuts cost and latency the most?
✅ A. Prompt caching on the system prompt
The repeated prefix is read from cache, so input is cheaper and the first token arrives faster.
❌ B. Stream the response · your answer
Streaming only changes how output arrives. You still pay full price for all 20k input tokens.
C. Raise max_tokens
This only caps output length. It has no effect on input cost.
D. Message Batches API
Cheaper, but results come back asynchronously, so latency goes up.
✕ Not quite. The answer is A.
💡 In one line: A big prefix that repeats should be cached. Streaming doesn't make input cheaper.

Why this design

  • Instant verdict at the bottom (Duolingo). You see right or wrong immediately, in the thumb zone, with a big Continue button.
  • A reason on every choice, visible without tapping (UWorld). UWorld's per-choice explanations are what its users praise most. Duolingo gets criticized for showing the answer without explaining it. The reason your answer was wrong is the most valuable part, so it's never hidden.
  • One-line takeaway first, then more depth if you want it (Brilliant). You can move fast when you get it, or dig in when you don't.
  • Diagram only when it helps. It's optional per question, not forced on every one.
  • Links to the flashcards and lesson, so a miss leads straight into studying that topic.
  • Dark mode only. Near-black background, soft violet accent, and green and red kept muted so they don't glare.
